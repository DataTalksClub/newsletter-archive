# DataTalks.Club Weekly: newsletter archive

Static archive of every issue of the DataTalks.Club Weekly newsletter, published with GitHub Pages at
**https://newsletter.datatalks.club**. It replaces the Mailchimp campaign archive. This repository is an
archive: never delete it or rewrite history.

- Plain HTML, no JavaScript framework, no analytics, no tracking pixels.
- Links are the original destinations, with no click-tracking wrappers.
- Unsubscribe/preferences/forward links, merge tags and preheader filler are removed.
- Images are copied into `images/` so the archive does not depend on Mailchimp.
- See [COVERAGE.md](COVERAGE.md) for the issue number to source table.

## Layout

```
issues/<slug>/meta.json     number, kind, title, date, preview, source
issues/<slug>/content.html  cleaned email (styles + body), no site chrome
images/                     downloaded images, content-addressed (sha1 of source URL)
build.py                    builds ./site (standard library only)
tools/clean.py              email -> clean archive HTML (needs beautifulsoup4, lxml; Pillow optional)
tools/add_issue.py          add one issue after a send
tools/import_mailchimp.py   one-off backfill from the Mailchimp API (already run)
.github/workflows/ci.yml    PR check: build + sanity checks
.github/workflows/pages.yml deploy ./site to GitHub Pages on push to main
```

Slugs: weekly issues are `weekly-N`; anything else is `YYYY-MM-DD-title`.

## Build locally

```bash
python3 build.py --check          # writes ./site, fails on missing images
python3 -m http.server -d site    # http://localhost:8000
```

## Add a new issue after a send

```bash
python3 -m pip install beautifulsoup4 lxml Pillow
python3 tools/add_issue.py --number 302 --date 2026-11-09 \
    --title "Subject line of the issue" --html path/to/sent.html
python3 build.py --check
git checkout -b issue-302 && git add issues images && git commit -m "Add issue #302"
gh pr create --fill     # CI builds the site; merge to publish
```

`--html` is the HTML as sent (`-` reads stdin). For a stand-alone sponsor email omit `--number`
(`--kind standalone`). Use `--source <url>` to record an original public URL. Existing slugs are
refused unless `--force`.

Automating this from Relay: the same output (two files per issue) can be committed with the GitHub
contents API; `content.html` only needs images as absolute `https://` URLs or `/images/...` files that
are already committed. Any push to `main` redeploys the site.

## Publishing and domain

- Pages source: GitHub Actions (`pages.yml`). `site/CNAME` is generated by `build.py`.
- DNS: `newsletter.datatalks.club` CNAME `datatalksclub.github.io` (Route53, managed in aws-infra).
- HTTPS is enforced in the repository Pages settings once the certificate is issued.
