What You Need to Do
  1. Pick a problem that interests you and find a dataset
  2. Describe the problem and how ML can help
  3. Prepare the data and run EDA
  4. Train several models, tune them, and pick the best
  5. Export your notebook to a script
  6. Package your model as a web service and deploy it with Docker

Project Tips

Keep these tips in mind when working on your project:

  • Pick a realistic dataset you understand: small enough to finish, big enough to learn
  • Start with a simple baseline model, then tune and compare a few
  • Document everything: problem, data, metrics, and setup steps
  • Refactor your notebook into scripts (train.py, predict.py, serve.py)
  • Dockerize early, don't wait till the last day
  • Peer review needs 3 completed reviews to pass
  • Cloud deployment = bonus points
  • Focus on reproducibility, not just performance

How to Submit and Review Projects
  1. Go to your course page
  2. Open the project submission form.
  3. Prepare your materials:
    • GitHub repo URL (you can use a separate repo or a subfolder in your course repo)
    • Commit ID of your final project version
    • (Optional) Up to 14 “learning in public” links: posts where you shared your progress
    • (Optional) Link to your FAQ contribution, if any
  4. Review your certificate name: it will appear exactly as entered. You can edit it under Enrollment Details -> Name on certificate
  5. Submit the form

Even after the deadline, you can still submit while the form remains open (it may be closed manually anytime).

Reviewing Peer Projects

Once the form closes, you'll automatically receive three peer review assignments.

Each assignment includes:

  • A GitHub project link
  • A specific commit hash to review
Here's what you need to do during peer review:
  1. Open each assigned project on GitHub
  2. Evaluate the project using the official criteria (problem description, reproducibility, deployment, etc.)
  3. For each criterion, assign points based on completeness and quality
  4. (Optional but recommended) Try to run the project locally to verify reproducibility.
  5. Leave short, constructive feedback: what worked well and what could be improved.
  6. Submit your review and record the time spent.
  7. (Optional) Review extra projects for additional learning
